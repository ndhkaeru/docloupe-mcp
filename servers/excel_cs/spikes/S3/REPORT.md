# S3 — response transport evidence (partial)

`dotnet run --project servers/excel_cs/spikes/S3/S3.csproj --configuration Release -- servers/excel_cs/src/DocLoupe.Excel.Server/bin/Release/net10.0/DocLoupe.Excel.Server.dll` launches the P2a server over stdio with the pinned MCP C# SDK 1.4.1. The client enumerated the P2a tools and `excel_undo`, received both `structuredContent` and an identical compact JSON `TextContent` from `excel_open`, and completed mixed `excel_apply` (including numeric and error typed formula caches, passing `expect.value`/`expect.formula` (including combined value+formula), and stale value/formula preconditions returned as structured `PRECONDITION_FAILED`) → `excel_save(copy)` with G7 assertions on those caches, rejection of a changed cell under `unchanged: true`, acceptance of an absent cell remaining absent, and `status=verified` → reopened and read cached results → `excel_undo` → `excel_close`.

The SDK client and probe server are separate projects; the S3 project compiles only its own `Program.cs`. The Release SDK smoke completed locally and is also run by the four-runner CI matrix.

The extended smoke also exercised `excel_find(query.formula_contains)` on an edited formula. On 2026-10-03 it exercised `excel_create` for `.xlsm` with multiple sheets, `expect.empty`, `save_as`, typed `excel_find(query.value)`, follow-up edit with `expect.value`, and `overwrite` with a backup. The SDK client passed on local Windows and Docker Linux; these observations are limited to the tested endpoints and do not close the model-visible client spike.

This establishes only **protocol delivery to the SDK client**. It does **not** establish which representation Claude Code, Claude Desktop or VS Code forwards to a model. Claude Code CLI 2.1.174 is installed and logged in locally; a first ad-hoc config probe did not expose `channel_probe` to its model, and a second file-config probe stopped at `error_max_budget_usd` before returning marker evidence. A subsequent restricted-tools probe produced only textual `<function_calls>` and unrelated invented S3 environment variable names; there was no actual tool-use turn or marker. These attempts **do not** establish which channel Claude Code forwards. Cancellation and image delivery are likewise unmeasured. The dual-channel envelope remains provisional until each target client is tested with a configured local server and its model-visible response is recorded. Do not label S3 complete based solely on this test.
